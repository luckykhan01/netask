Задача: система управления заказами

Нужно разработать приложение для управления заказами в небольшом магазине.

В системе есть пользователи, товары и заказы.
Пользователь может создавать заказ, добавлять в него товары и менять статус заказа.

Основные требования
	1. Модель предметной области (ООП)
	Создать классы:
	- Пользователь (id, имя, email)
	- Товар (id, название, цена)
	- Заказ (id, пользователь, список товаров, статус, дата создания)

	Использовать:
	- инкапсуляцию
	- enum для статуса заказа
	- композицию (заказ содержит товары)

	2. Логика приложения
	- создание пользователя
	- добавление товаров
	- создание заказа для пользователя
	- добавление / удаление товаров из заказа
	- подсчёт общей суммы заказа
	- смена статуса заказа (NEW → PAID → SHIPPED → COMPLETED)

	3. Работа с базой данных
	- использовать реляционную БД (H2 / PostgreSQL / MySQL)
	- хранить пользователей, товары и заказы
	- реализовать CRUD-операции
	- использовать JDBC или JPA (на выбор)

	4. Структура кода
	- разделить ответственность (model / service / repository)
	- не писать всю логику в одном классе
	- использовать интерфейсы там, где это оправдано
	- обрабатывать ошибки (пустой заказ, несуществующий id и т.д.)

	5. Дополнительно (по желанию)
	- сортировка заказов по дате или сумме
	- поиск заказов пользователя
	- логирование действий


Формат реализации (на выбор)
	1. Консольное приложение
	   Управление через меню в терминале.

	2. Spring Boot приложение
	   - REST API
	   - простой клиент (Postman / Swagger / минимальный frontend)


Решение, тесты и UI-дизайн не требуются — важны чистый код, логика и архитектура.
